# v1.1.0 图片识别与用药日程

## 功能

- 今日：九组本地果蔬大小示意图片，随孕周切换。
- 资料：药名与明确的服用时间原文识别、本地时间计算、保存前核对。
- 日程：拍照录入药盒/说明书/已有处方，后台AI只提取原文药名及服用时间要求；核对后生成每日固定时间日程。
- 记录：上传报告图片整理原文，编辑核对后保存本地文字记录。不生成诊断、正常异常或个性化用药判断。
- 上传图片前逐次单独确认；退出识别页取消请求并清理临时图片；失败显示真实错误，不用样例替代。

## 后端部署与小程序配置（正式上传前必须完成）

1. 后端服务部署本版本的 `server/`，配置 `OPENAI_API_KEY`、可选 `OPENAI_MODEL`，密钥只放在服务端环境。
2. 当前Render配置部署到新加坡。启用真实用户图片前，核对实际运营主体、数据处理和出境适用要求，并完善公众平台隐私指引。
3. 在 `miniprogram/config.ts` 设置 `API_BASE_URL` 为真实可用的HTTPS源地址，不含路径、尾部斜杠或密钥。默认空值会明确禁用上传识别。
4. 微信公众平台的服务器域名中加入该API的 `request` 合法域名；保持域名校验开启。
5. `GET /api/health` 应返回 `ok:true, configured:true`；分别真机测试两种图片识别、取消上传、错误重试、核对保存。
6. `node scripts/validate-miniprogram.mjs miniprogram --production` 必须通过。源码校验允许域名为空，生产校验不允许。
7. 上传新开发版本建议版本号 `1.1.0`。只上传，不撤回此前审核，不自动提审或发布。

## API

- `POST /api/extract-medication`：`{ imageDataUrl }`，返回 `{ sourceText, name, timingText }`。药名与时间字段必须有原文依据；不清楚时留空。
- `POST /api/extract-report`：`{ mode: "record_only", imageDataUrl }`，返回已有的报告文字整理结构。
- JPG/PNG/WebP，上限6MB。后端校验图片签名，未配置密钥或调用失败不会返回伪造结果。
- 两种识别接口共享每进程每分钟30次请求和最多2个同时AI调用的限额；多实例部署时需在网关统一限额。此限额不等于用户鉴权。

## 当前边界

- 只有原文识别和时间换算，不按药名推断用法。药物多次服用分别录入，复杂要求手动确认。
- 时间换算使用今日三餐；修改三餐后需重新生成。固定每日时间不是微信消息推送。
- AI Key不进入小程序，图片不写入后端磁盘，使用 `store:false`；服务商安全监测保留不等于零保留。
- 小程序使用本机保存。识别页保存报告时仅保存核对后的文字；若需保留照片，可在个人记录编辑页添加本地附件。
- 微信上传须使用已登录的开发者工具并开启服务端口；公众平台“版本管理”页面不是直接上传源码ZIP的入口。

新增按孕周展示的宝宝大小趣味插图；支持填写服用时间要求并核对生成用药日程；新增药品图片原文识别及报告文字整理，结果经用户编辑确认后保存。图片上传前单独确认，完善隐私说明、错误重试和本地数据管理。不提供诊断或个性化用药建议。
