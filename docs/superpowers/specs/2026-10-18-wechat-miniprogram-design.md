# 孕期助手微信小程序设计规格

## 1. 目标

在保留现有 React Web Demo 的同时，在同一仓库新增一套可提交微信正式审核的原生 TypeScript 小程序。首版面向个人主体，以审核通过为优先目标，提供孕期资料、孕周状态、产检日程、饮食与补剂日程、个人记录，以及受限的报告照片文字整理能力。

首版不提供诊断、正常或异常判断、风险推断、医学建议、个性化用药建议或药物推荐。报告能力统一表述为“文字提取、原文摘要与术语释义”，不得在界面、接口或提示词中表述为医学诊断或治疗建议。

## 2. 产品范围

### 2.1 今日

- 根据末次月经日期估算当前孕周和预产期。
- 展示与当前孕周匹配的宝宝发育描述。
- 展示下一次产检事项和准备清单。
- 展示当天未完成的饮食、补剂和个人日程。
- 高危因素和正在服用的药物只按用户输入原文记录并提醒向医生说明，不生成个性化建议。

### 2.2 日程

- 管理产检、早餐、午餐、晚餐、加餐、补剂和自定义事项。
- 支持新增、编辑、删除和勾选完成。
- 提供通用的均衡饮食示例，明确标记为非个体化建议。
- 不使用订阅消息，不进行微信主动推送。

### 2.3 个人记录

- 支持日期、标题、正文、标签和照片附件。
- 用户可主动选择一张报告照片并发起文字整理。
- 解析只返回原文文字、报告日期、报告名称、检查项目、原文数值、原文摘要和通用术语释义。
- 解析不得返回正常或异常状态、疾病推断、风险等级、治疗方案、检查建议、就医建议或药物建议。
- 用户必须检查并确认结果后，才能将文字结果保存为本地记录。
- 原始照片和确认后的记录保存在小程序本机；服务端不持久化原图。

### 2.4 我的资料

- 收集末次月经第一天。
- 收集单胎、双胎或多胎。
- 收集高危因素自由文本。
- 收集当前正在服用的药物自由文本。
- 支持随时修改资料和清除本地全部数据。

## 3. 信息架构

小程序使用三个底部 Tab：

1. `今日`：孕周状态、宝宝状态、下次产检和今日事项。
2. `日程`：产检、饮食、补剂和自定义日程。
3. `记录`：文字记录、照片附件和报告文字整理。

`我的资料`、`隐私说明`、`关于`和`清除数据`从页面顶部或设置入口进入，不占用底部 Tab。

首次启动且没有孕期资料时，直接进入资料引导页。完成资料后进入“今日”。

## 4. 技术架构

### 4.1 仓库结构

现有 `src/`、`server/` 和 Vite 配置保持可运行。新增：

```text
miniprogram/
  app.json
  app.ts
  app.wxss
  project.config.json
  pages/
    onboarding/
    today/
    schedule/
    records/
    record-editor/
    profile/
    privacy/
  components/
  services/
  storage/
  domain/
  types/
  assets/
```

小程序使用微信原生 WXML、WXSS 和 TypeScript，不引入 Taro、uni-app 或 UI 框架。现有 Web 版继续使用 React。

### 4.2 数据存储

- 使用 `wx.setStorageSync` 和 `wx.getStorageSync` 保存资料、日程、记录和隐私同意状态。
- 所有本地数据放在一个带版本号的存储对象中，以支持后续迁移。
- 照片使用小程序本地文件能力保存文件路径；删除记录或清除全部数据时同步删除已保存文件。
- 首版不登录、不建立用户账号、不使用云数据库、不跨设备同步。

### 4.3 后端接口

新增 `POST /api/extract-report`，请求包含图片和明确的 `mode: "record_only"`。接口响应为一次性 JSON，不使用流式 NDJSON，避免依赖小程序端流式响应能力。

响应结构包含：

- `sourceText`
- `reportTitle`
- `reportDate`
- `items[]`，每项仅包含 `name`、`value`、`unit`、`sourceText`
- `summary`
- `terms[]`，每项包含 `term` 和通用释义 `definition`
- `limitations`

服务端在返回前执行结构验证和禁用内容过滤。若模型返回诊断、异常判断、风险或建议字段，接口必须拒绝该结果，而不是删除字段后继续返回。

现有 `/api/parse-report` 保留给 Web Demo，不在小程序中调用。

### 4.4 隐私与数据流

1. 首次启动展示隐私说明并记录版本。
2. 用户填写资料，数据仅写入本机。
3. 用户选择照片时，先显示图片处理说明并取得单次确认。
4. 确认后将图片发送到 HTTPS 后端；服务端转发至已配置的模型服务并设置不持久化。
5. 服务端返回受限结果，用户在编辑页核对。
6. 用户点击保存后，本地写入确认后的记录；取消则不保存解析文字。

页面不得声称照片“只在本机处理”。页面应准确说明照片会发送至服务端和模型服务进行文字整理。

## 5. 状态与错误处理

- 图片选择、压缩、上传、识别和生成摘要分别显示状态。
- 上传失败、网络超时、图片过大、格式不支持和解析内容不完整均提供明确重试入口。
- API 未配置、额度不足或模型服务不可用时，只显示技术错误，不回退到伪造的演示结果。
- OCR 结果始终可编辑，并明确提醒用户对照原始报告核验。
- 孕周计算遇到无效或未来日期时阻止保存并说明原因。
- 本地文件丢失时保留文字记录，并标记附件不可用。

## 6. 审核边界与文案

- 功能名称使用“报告文字整理”或“术语释义”，不使用“诊断”“风险评估”“异常分析”“治疗建议”。
- 术语释义必须是通用定义，不结合用户指标给出结论。
- 每个结果页显示“仅用于个人记录整理，请以原报告和医生解释为准”。
- 不提供在线问诊、医生匹配、药物推荐、剂量调整或健康风险评分。
- 服务类目按小程序后台实际可选范围和实际功能如实选择，不通过修改名称规避类目要求。

## 7. 测试策略

- 纯函数单元测试：孕周、预产期、日程生成、日期校验和数据迁移。
- 存储测试：资料、日程、记录、照片路径、清除数据和版本迁移。
- API 测试：合法提取结果、禁用内容拒绝、无密钥、超时、图片大小和格式。
- 页面测试：首次引导、资料修改、日程增删改和完成状态、记录确认保存。
- 微信开发者工具手工检查：编译、预览、真机照片选择、合法域名、隐私提示和断网状态。
- 发布前回归现有 Web 的 `npm test` 与 `npm run build`。

## 8. 发布与用户同步事项

用户需要同步完成：

1. 在微信公众平台注册个人主体小程序并取得 AppID。
2. 填写小程序名称、头像、简介和符合实际功能的服务类目。
3. 准备并配置一个自有 HTTPS API 域名；正式发布不能依赖 localhost。
4. 在“开发管理 - 开发设置”中配置 `request` 合法域名。
5. 在“用户隐私保护指引”中如实声明孕期资料、照片和健康相关文本的处理用途。
6. 将 AppID 填入本地 `project.private.config.json` 或开发者工具设置；AppSecret 不进入仓库。
7. 使用微信开发者工具完成预览、真机测试和代码上传。
8. 在版本管理中填写功能页面、测试说明和审核备注，提交正式审核；审核通过后手动发布。

开发工作负责：

1. 创建原生小程序工程和页面。
2. 迁移孕周、日程和记录逻辑。
3. 实现本地存储、照片保存和隐私流程。
4. 实现受限报告文字整理接口及内容边界测试。
5. 补充项目说明、发布检查表和审核说明模板。
6. 提交并同步 GitHub。

## 9. 非目标

- 微信登录、手机号授权和账号体系。
- 云端记录同步、多人共享和跨设备恢复。
- 微信订阅消息或主动提醒。
- 在线问诊、诊断、风险评估、指标正常异常判断。
- 医学建议、就医建议、治疗建议、药品推荐或剂量建议。
- 支付、会员和商业化功能。

## 10. 验收标准

- 微信开发者工具可以导入、编译和预览 `miniprogram/`。
- 用户能完成资料录入并看到计算后的孕周状态。
- 用户能新增、编辑、删除和完成日程。
- 用户能创建文字记录、保存照片并确认 OCR 整理结果。
- 小程序端看不到任何医学判断或个性化建议。
- 清除数据会删除本地资料、日程、记录和已保存附件。
- 现有 Web Demo 和 API 测试不回归。
- 仓库中不包含 AppSecret、OpenAI API Key、真实报告照片或其他敏感数据。
